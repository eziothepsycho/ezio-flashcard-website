# Database

MySQL schema for the backend (Phase 2+). It is the current browser data model
promoted to real tables — same shapes, same ownership rules, so the clients
barely notice the change.

## Tables

```sql
-- Accounts: username + password only. No email, no phone, no profile.
CREATE TABLE users (
  id            CHAR(36)     NOT NULL,          -- UUID v4, same ids as today
  username      VARCHAR(20)  NOT NULL,          -- stored as typed (display casing)
  password_hash VARCHAR(255) NOT NULL,          -- bcrypt or argon2id, server-side only
  created_at    DATETIME(3)  NOT NULL,
  updated_at    DATETIME(3)  NOT NULL,
  PRIMARY KEY (id),
  UNIQUE KEY uq_users_username (username)       -- case-insensitive via collation
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_0900_ai_ci;

-- A set belongs to exactly one account.
CREATE TABLE sets (
  id          CHAR(36)     NOT NULL,
  user_id     CHAR(36)     NOT NULL,
  title       VARCHAR(255) NOT NULL,
  description TEXT         NULL,
  created_at  DATETIME(3)  NOT NULL,
  updated_at  DATETIME(3)  NOT NULL,
  PRIMARY KEY (id),
  KEY idx_sets_user (user_id),
  CONSTRAINT fk_sets_user FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE CASCADE
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4;

-- A card belongs to a set; its owner is the set's owner. No user_id here.
CREATE TABLE cards (
  id              CHAR(36) NOT NULL,
  set_id          CHAR(36) NOT NULL,
  term            TEXT     NOT NULL,
  definition      TEXT     NOT NULL,
  learning_status ENUM ('known', 'learning') NULL,  -- NULL = not graded yet
  created_at      DATETIME(3) NOT NULL,
  updated_at      DATETIME(3) NOT NULL,
  PRIMARY KEY (id),
  KEY idx_cards_set (set_id),
  CONSTRAINT fk_cards_set FOREIGN KEY (set_id) REFERENCES sets (id) ON DELETE CASCADE
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4;
```

Framework tables that come for free: `migrations` (Laravel) and either
`personal_access_tokens` (Sanctum) or a hand-rolled `tokens` table for Express.

## Mapping from the current browser model

| Today (`localStorage`) | Column | Notes |
| --- | --- | --- |
| `users[].id` | `users.id` | UUID — kept, so migration needs no id mapping |
| `users[].username` | `users.username` | as typed |
| `users[].usernameLower` | *collation* | the column exists only because JS comparison is case-sensitive; MySQL's case-insensitive collation replaces it (on MySQL 5.7 / MariaDB use `utf8mb4_unicode_ci`, or a generated stored `username_lower` + unique index) |
| `users[].passwordHash` + `salt` | `users.password_hash` | **not portable** — the local hash is client-side salted SHA-256; passwords are re-entered once |
| `users[].createdAt` | `users.created_at` | |
| `sets[].id` / `userId` / `title` / `description` | `sets.*` | timestamps ISO → `DATETIME(3)` |
| `cards[].id` / `setId` / `term` / `definition` / `learningStatus` | `cards.*` | `learningStatus` absent today ⇒ `NULL` |

## Ownership queries (the port of `ownsSet()`)

Every query is scoped by the authenticated user. Foreign rows must come back
empty — never an error that reveals they exist.

```sql
-- my sets (same order as today's array: oldest first)
SELECT * FROM sets WHERE user_id = ? ORDER BY created_at, id;

-- one set, only if it is mine   (no row => API returns 404)
SELECT * FROM sets WHERE id = ? AND user_id = ?;

-- cards of a set, only if the set is mine
SELECT c.* FROM cards c
JOIN sets s ON s.id = c.set_id
WHERE c.set_id = ? AND s.user_id = ?
ORDER BY c.created_at, c.id;

-- edit / grade a card, only if its set is mine
UPDATE cards
SET term = ?, definition = ?, learning_status = ?, updated_at = ?
WHERE id = ? AND set_id IN (SELECT id FROM sets WHERE user_id = ?);

-- delete a card, only if its set is mine
DELETE FROM cards WHERE id = ? AND set_id IN (SELECT id FROM sets WHERE user_id = ?);

-- delete a set: the FK cascade removes its cards (mirrors today's cascade)
DELETE FROM sets WHERE id = ? AND user_id = ?;
```

Laravel equivalent: never look a card up directly — always
`$request->user()->sets()->findOrFail($setId)` for set routes, and
`Card::whereHas('set', fn ($q) => $q->where('user_id', $user->id))->findOrFail($cardId)`
for card routes (or a global scope on `Card`). Express: put the same
`set_id IN (SELECT id FROM sets WHERE user_id = ?)` condition in every card
statement — no exceptions.

## Design decisions worth remembering

- **UUID primary keys** (`CHAR(36)`, generated by the server, or supplied by the
  client when it already has one) — keeps migration id-stable and makes a future
  offline queue possible without collision handling. `BINARY(16)` +
  `UUID_TO_BIN()` is the space-optimised option if we ever need it; not now.
- **No `user_id` on `cards`.** Ownership stays derived through `sets`, so there is
  exactly one place it can be wrong.
- **Case-insensitive unique usernames** live in the collation, not in a duplicated
  lowercase field.
- **`learning_status` stays on `cards`** to match today's behaviour. If sets are
  ever shared between accounts, per-user progress needs its own
  `card_progress(card_id, user_id, status)` table — out of scope.
- **`ON DELETE CASCADE`** on both foreign keys reproduces the current "deleting a
  set takes its flashcards with it" rule.
- **Titles are not unique** (today they aren't either) — two sets may share a title.
- Timestamps are stored as UTC `DATETIME(3)` and serialised as ISO-8601 with `Z`,
  exactly like today's `new Date().toISOString()` values, so `new Date(...)`
  parsing in the UI keeps working.
